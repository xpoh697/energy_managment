# DEBATE: Fix Sell Window Duration (Mismatch in Tolerance Settings)

## Archi (Lead Architect)
**Проблема:** В моде `get_market_strategy` для режима `sell` используется глобальная переменная `tolerance` (которая тянется из настройки `CONF_PRICE_TOLERANCE`, предназначенной для покупки). При этом специфическая настройка `CONF_PRICE_SELL_TOLERANCE` игнорируется, хотя она импортирована. Это приводит к тому, что если пользователь ставит допуск продажи 0.06, а системный допуск (или допуск покупки) меньше, то часы с ценой чуть ниже пиковой отфильтровываются.

**Решение:** 
1. Полностью развести логику: ввести `buy_tolerance` и `sell_tolerance`.
2. `buy_tolerance` читается из `CONF_PRICE_TOLERANCE`.
3. `sell_tolerance` читается из `CONF_PRICE_SELL_TOLERANCE`.
4. Убрать взаимозависимость (fallback), чтобы настройки были полностью независимы, как просит пользователь.

---

## Skeptic (Senior SRE/Security)
**Критика решения:**
1. **Обратная совместимость:** Если убрать фоллбек, пользователи, которые настроили только один глобальный допуск, могут заметить изменение поведения (возврат к дефолту 0.1 для второй переменной). Но раз пользователь настаивает на изоляции — это допустимый риск.
2. **Дефолты:** Нужно жестко задать 0.0 как стандартное значение для обоих, если в базе пусто.
3. **Чистота кода:** Переименование `tolerance` в `buy_tolerance` внутри функции `get_market_strategy` потребует правки вызовов в блоке `mode == "buy"`.

---

## Final Approval (Skeptic)
Я одобряю решение. Полная изоляция параметров исключает логические ошибки при настройке разных стратегий для покупки и продажи.
- `buy_tolerance` и `sell_tolerance` инициализируются независимо.
- Все вызовы `get_peaks` обновлены.

**Статус: ОДОБРЕНО**
