## [2026-05-13 13:11] Задача: Исправление «отравления» SOC в UI-прогнозе.

### Archi
Обнаружил критическую логическую ошибку в цикле формирования данных для UI в `sensor.py`. Цикл симуляции SOC всегда начинается с 00:00 текущего дня, используя текущий реальный SOC как стартовую точку. В итоге для текущего часа (например, 13:00) мы получаем SOC, из которого уже 13 раз вычли нагрузку, хотя эти часы уже в прошлом. Это создает иллюзию падения SOC и «потери солнца». Нужно начинать обновление `batt_soc` только с текущего часа.

### Skeptic
1. **Целостность цикла:** Если мы просто пропустим часы до `now.hour`, нужно убедиться, что `hourly_data` для прошлых часов всё равно заполняется корректно (вероятно, из истории или просто текущим SOC).
2. **Точность:** Для текущего часа (`h == now.hour`) мы должны использовать реальный SOC как базу, а не результат симуляции.
3. **Производительность:** Пропуск лишних итераций только на пользу.

### Заключение
В цикле формирования `hourly_data` в `sensor.py` добавить условие: расчет и обновление `batt_soc` производить только для часов `>= now.hour` (для текущего дня) и для всех часов завтрашнего дня. Для прошлых часов использовать текущий SOC без изменений. Это восстановит корректность отображения «солнечного» заряда. Перед применением сделать GIT COMMIT.
