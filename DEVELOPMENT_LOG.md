# Energy Management System - Development Log (AI-Persist)

Данный файл предназначен для того, чтобы ИИ-ассистент мог быстро восстановить контекст проекта и не повторять ошибки прошлых сессий.

## 💾 Данные и диагностика
- **Backup базы:** `\\192.168.100.5\config\energy_management_backup.json`
- **Инструкция для ИИ:** Если тебе не хватает данных для понимания картины или дебага, **всегда проси пользователя обновить бэкап** и прислать путь к нему.

## 🏗 Архитектура и ключевая логика

### 1. Симуляция заряда (StrategyEngine.run_soc_simulation)
- **Функция:** Просчитывает SOC на 24-48 часов вперед.
- **Возвращаемое значение:** `(soc_dict, log_list, overflow_kwh)`. 
- **⚠️ ВАЖНО:** Всегда ожидает распаковку **трех** значений. `overflow_kwh` — это потенциальный экспорт (излишки AC после 100% заряда).

### 2. Расчет базового потребления (Base Consumption)
- **Логика:** `Base = Total_Meter - Managed_Loads`.
- **Managed Loads:** Нагрузки, имеющие свои датчики энергии (бойлер, посудомойка и т.д.).
- **Защита от скачков (v11.1.3):**
    - Если дельта датчика за один замер > 2.0 кВт⋅ч, она игнорируется.
    - Если значение датчика падает (сброс розетки), дельта считается равной 0, базовая линия обновляется.
    - При загрузке данных значения > 20 кВт⋅ч обнуляются как ошибочные.

### 3. Сенсор отклонения (ConsumptionDeviationSensor)
- Сравнивает текущую нагрузку (`actual_base`) с историческим профилем.
- Чтобы избежать "-100% отклонения", формула `actual_base` включает текущий почасовой аккумулятор: 
  `total_actual = sum(profile_history) + current_hour_accumulator`.

### 4. Потенциальный экспорт (PotentialExportTodaySensor)
- Берет `overflow_kwh` из последней симуляции.
- Класс устройства: `energy`, класс состояния: `total` (для корректной работы в HA).

## 📌 Особенности конфигурации
- Базовая нагрузка ограничена `1.2 кВт` в некоторых расчетах для стабильности (чтобы аномальные всплески не ломали стратегию).
- Ожидаемый SOC на утро рассчитывается с учетом КПД батареи и стоимости деградации.
