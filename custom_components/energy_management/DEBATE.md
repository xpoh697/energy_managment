## [2026-05-14 16:21] Задача: с карточкой проблема. Работает только в локальной сети. Если снаружи смотрб выдает ошибку конфигурации

### Archi
Ошибка "Custom element doesn't exist" (ошибка конфигурации карточки) при доступе снаружи почти всегда связана с тем, что внешний доступ (через Reverse Proxy, NGINX, Cloudflare) или мобильное приложение (WebView) блокирует загрузку JS файла карточки.
Причины в текущем коде `__init__.py`:
1. Карточка раздается по пути `/api/energy_management/static/...`. Многие прокси-серверы из соображений безопасности по умолчанию блокируют внешние неавторизованные запросы к любым эндпоинтам, начинающимся с `/api/`.
2. В `CardStaticView` не включен CORS (`cors_allowed = True`), из-за чего WebView мобильного приложения может отклонить загрузку скрипта.
Решение: Уйти от префикса `/api/`, переименовав путь в `/energy_management_static/`, и включить CORS.

### Skeptic
1. **Обновление Lovelace**: Если мы изменим URL, обновится ли он в ресурсах Lovelace у пользователя? Да, наш код в `_async_register_lovelace_resource` ищет совпадение по имени файла и сам перезапишет URL на новый.
2. **Кэш**: Пользователю обязательно придется сбросить кэш мобильного приложения (или потянуть вниз для обновления) после применения патча, иначе приложение будет искать карточку по старому локальному пути.
3. **Безопасность**: Убрав `/api/`, мы просто выносим статику в корень (как делает HACS с `/hacsfiles/`). Это безопасно, так как мы отдаем только один конкретный JS файл.

### Заключение
1. В `__init__.py` заменить префикс URL карточки с `/api/energy_management/static` на `/energy_management_static`.
3. Сделать бамп версии до `v11.9.619`.

## [2026-05-14 16:25] Опровержение: "так тоже по api зарегена другая интеграция и работает"

### Archi
Пользователь прав. Если другая интеграция работает через `/api/...`, значит проблема не в префиксе URL, а в **обработчике** этого URL. 
В нашем коде используется самописный класс `CardStaticView`, который:
1. Не поддерживает CORS (`cors_allowed = True` отсутствует).
2. Не умеет обрабатывать запросы `HEAD` и `OPTIONS`, которые отправляют внешние прокси (Cloudflare, NGINX) для проверки доступности и кэширования.
3. Не поддерживает сжатие (gzip/brotli), ожидаемое внешним доступом по домену.

Решение: Полностью удалить самописный `CardStaticView` и использовать встроенный в Home Assistant метод `hass.http.register_static_path`. Он "из коробки" поддерживает CORS, сжатие и все необходимые HTTP-заголовки для внешних доменов.

### Skeptic
1. **Совместимость**: `register_static_path` — это стандартный API Home Assistant, он безопаснее и надежнее самописного View.
2. **Кэш**: Использование `cache_headers=False` при регистрации пути оставит кэширование на усмотрение браузера, но наш параметр `?v=v11.9.619` в URL всё равно принудительно обновит кэш у пользователя.

### Заключение
1. В `__init__.py` удалить класс `CardStaticView`.
2. В `_async_register_card` заменить `hass.http.register_view(...)` на `hass.http.register_static_path(...)`.
3. Оставить URL прежним (`/api/energy_management/static/...`).
4. Версия -> `v11.9.619`.
