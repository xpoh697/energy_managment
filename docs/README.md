# Energy Management — Документация интеграции

> Интеграция для Home Assistant, реализующая интеллектуальное управление потреблением и генерацией энергии.  
> Отслеживает профили потребления/генерации, рассчитывает энергетический бюджет и автоматически формирует команды для инвертора.

## Архитектура

```
EnergyProfileManager  (менеджер — ядро интеграции)
│
├── Сбор данных
│   ├── _async_state_changed      — триггер при изменении энергосенсоров
│   ├── _poll_instant_power       — опрос мощности каждую минуту
│   └── _async_reset_hour         — сброс/сохранение накопителей каждый час
│
├── Аналитика
│   ├── get_average_profile()     — усреднённый почасовой профиль за N дней
│   ├── get_todays_profile()      — реальный профиль за текущий день
│   ├── get_budget_and_permissions()  — расчёт энергобюджета и разрешений
│   ├── get_market_strategy()     — рыночная стратегия (BUY/SELL)
│   ├── get_battery_state()       — SOC, ёмкость, энергия батареи
│   ├── get_forecast_value()      — сумма значений прогноза генерации
│   ├── get_current_occupancy()   — текущий подсчёт людей дома
│   ├── get_occupancy_coefficient() — коэффициент присутствия для коррекции прогноза
│   ├── get_occupancy_coefficient() — коэффициент присутствия для коррекции прогноза
│   ├── get_efficiency_coefficient() — коэффициент КПД инвертора (потери DC↔AC конвертации)
│   └── get_gen_forecast_coefficient() — масштабирование генерации по прогнозу
│
└── Вспомогательные
    ├── get_sensor_float()        — безопасное чтение float из сенсора HA
    ├── get_setting()             — чтение настройки с типизированным default
    ├── get_cc_cv_ratio()         — кривая CC/CV заряда батареи
    ├── export_data() / import_data() — экспорт/импорт истории в JSON
    └── _update_prices_from_sensor()  — парсинг ценовых атрибутов (NordPool, ENTSO-E и др.)
```

| `dynamic_soc_sell` | True | Умный расчёт резервного SOC при продаже |
| `min_soc_buy` | 10.0 | Критический минимум SOC (аварийный заряд) |

## Хранение данных

Данные сохраняются в HA Storage (`/config/.storage/energy_management_<entry_id>`) как JSON.

### Структура `data`

```json
{
  "consumption_base": {
    "0": [{"v": 0.312, "wd": 1, "occ": 2}, ...],
    "1": [...],
    ...
    "23": [...]
  },
  "consumption_total": {
    "0": [{"v": 0.450, "wd": 1, "occ": 2}, ...],
    ...
  },
  "generation": {
    "0": [{"v": 0.0, "wd": 1}, ...],
    "13": [{"v": 2.1, "wd": 3}, ...],
    ...
  },
  "prices_buy": {
    "2025-03-10": {"0": -0.05, "1": 0.02, ..., "23": 0.18}
  },
  "prices_sell": {
    "2025-03-10": {"14": 0.35, "15": 0.42}
  },
  "forecast_history": [
    {"actual": 18.4, "forecast": 20.1, "date": "2025-03-09"},
    ...
  ],
  "temp_daily_gen": 12.3,
  "temp_max_forecast": 21.0,
  "sensor_last_values": {
    "sensor.solar_energy": 1234.56
  },
  "settings": {
    "price_buy_limit": 0.05,
    "battery_max_power": 5.0
  }
}
```

| Поле | Описание |
|------|----------|
| `consumption_base` | Базовое потребление (без управляемых нагрузок). `v` — значение кВт·ч, `wd` — день недели (0=пн, 6=вс), `occ` — кол-во людей дома |
| `consumption_total` | Полное потребление (включая deduct-сенсоры, для расчёта загрузки батареи) |
| `generation` | Генерация (солнечные панели) |
| `prices_buy` / `prices_sell` | Тарифы по часам на сегодня и завтра |
| `forecast_history` | История сравнений прогноза vs факта генерации. Используется для коэффициента надёжности |
| `temp_daily_gen` | Накопленная за сутки генерация (сбрасывается в 00:00) |
| `temp_max_forecast` | Максимальный прогноз за текущий день (обновляется по максимуму) |
| `sensor_last_values` | Последние считанные значения сенсоров (для расчёта дельты после перезапуска) |

### Запись данных каждый час (`_async_reset_hour`)

1. Вычисляется `past_hour = (now.hour - 1) % 24`
2. Получается текущий счётчик присутствия (`occ_count`)
3. Накопленные значения `current_consumption_base`, `current_consumption_total`, `current_generation` записываются в историю
4. История обрезается до `max_days` записей
5. В 00:00 — сброс `daily_deduct_consumption`, обновление `forecast_history`
6. Счётчики обнуляются

### Обработка дельты (`_async_state_changed`)

```
new_val = current sensor reading
old_val = last recorded value

delta = new_val - old_val

if delta < 0:       # сброс счётчика сенсора
    delta = new_val  # принять как новое значение с нуля

if delta > 100 kWh: # невозможный скачок — игнорировать, сбросить базу
    log warning, reset baseline, return

apply delta →
  consumption_base += delta  (если сенсор потребления)
  consumption_total += delta (если сенсор потребления)
  current_generation += delta (если генерация)
  consumption_base -= delta  (если deduct-сенсор — вычитается из базы)
  daily_deduct_consumption[id] += delta
```

## Алгоритмы ядра

### `get_average_profile(profile_type, days, day_type, occupancy_filter)`

Возвращает словарь `{"0": float, "1": float, ..., "23": float}` — среднее значение кВт·ч за час за последние `days` дней.

**Фильтры:**
- `day_type`: `"all"` / `"weekday"` (пн-пт, wd < 5) / `"weekend"` (сб-вс, wd >= 5)
- `occupancy_filter`: `None` / `"home"` (occ > 0) / `"away"` (occ == 0)

Для каждого часа: `среднее = sum(valid_values) / len(valid_values)`. При 0 значений возвращает `0.0`.

### `get_cc_cv_ratio(soc)`

Моделирует поведение BMS при зарядке:

| SOC | Коэффициент |
|-----|-------------|
| ≤ 85% | 1.0 (CC — полная мощность) |
| 85–92% | 1.0 → 0.7 (линейное снижение) |
| 92–97% | 0.7 → 0.2 (CV — плавное снижение) |
| 97–98% | 0.2 → 0.1 |
| > 98% | 0.1 → 0.02 (финальный CV) |

Результат клипируется в `[0.02, 1.0]`.

### `get_gen_forecast_coefficient(forecast_value, prof_gen, hour_start, hour_end)`

Масштабирует историческую генерацию относительно внешнего прогноза:

```
hist_sum = sum(prof_gen[h] for h in [hour_start, hour_end))
coefficient = forecast_value / hist_sum  (если hist_sum > 0)
```

Используется для корректировки BMS-симуляции.

## Описание всех сенсоров

### 1. Профиль Потребления / Генерации (Averaged Profile)

**Создаётся:** 4 штуки для потребления + 4 для генерации (периоды: 7, 30, 365 дней + кастомный).

**Имена:**
- `Профиль Потребления (Неделя)`, `...Месяц`, `...Год`, `...Кастом (N дн.)`
- `Профиль Генерации (Неделя)`, и т.д.

**Состояние (state):** Суммарное среднедневное потребление / генерация в кВт·ч  
*(Сумма всех 24 часов усреднённого профиля)*

**Атрибуты потребления:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `base_profile` | `dict[str, float]` | Почасовое среднее базового потребления за N дней (без deduct-сенсоров). Все дни без фильтра. Ключи: `"0"` — `"23"` |
| `base_profile_weekday` | `dict[str, float]` | То же, но только по **рабочим дням** (пн–пт) |
| `base_profile_weekend` | `dict[str, float]` | То же, но только по **выходным** (сб–вс) |
| `total_profile` | `dict[str, float]` | Почасовое среднее **полного** потребления (включая deduct-сенсоры) |
| `total_daily_average` | `float` | Среднесуточное полное потребление (кВт·ч) — сумма `total_profile` |

**Атрибуты генерации:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `profile` | `dict[str, float]` | Почасовое среднее генерации за N дней. Все дни объединены |

> **Примечание:** `base_profile` используется для расчёта бюджета (ожидаемое потребление). `total_profile` — для симуляции батареи в рыночной стратегии.

### 2. Текущее почасовое накопление (Live Hourly Sensor)

**Имена:** `Текущее почасовое потребление`, `Текущая почасовая генерация`

**Тип класса:** `SensorStateClass.TOTAL` — сбрасывается раз в час  
**Класс устройства:** ENERGY (кВт·ч)

**Состояние:** Накопленное значение за текущий час (с начала текущего часа до сейчас), в кВт·ч.

Для потребления — значение `current_consumption_base` (базовое, без deduct).

**Восстановление после перезапуска:** Использует `RestoreEntity` — значение восстанавливается из последнего состояния HA.

**Атрибуты (потребление):**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `total_consumption` | `float` | Полное накопленное потребление за текущий час, включая deduct-сенсоры |

**Атрибуты (генерация):** Нет дополнительных атрибутов.

### 3. Профиль сегодняшнего дня (Today Profile Sensor)

**Имена:** `Потребление за сегодня (Профиль)`, `Генерация за сегодня (Профиль)`

**Состояние:** Сумма накопленных значений за все завершённые часы сегодняшнего дня (кВт·ч).

Текущий (незавершённый) час тоже включается — из аккумулятора `current_consumption_base` / `current_generation`.

**Атрибуты:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `hourly_profile` | `dict[str, float]` | По часам за сегодня. Ключи `"00"` — `"23"`. Завершённые часы — из истории, текущий час — из аккумулятора, будущие — `0.0` |

### 4. Профицит энергии до утра (Energy Budget Sensor)

**Имя:** `Профицит энергии до утра`

**Единица:** кВт·ч

**Состояние:** Расчётный энергетический бюджет — сколько энергии останется после покрытия прогнозируемого потребления до 08:00 следующего дня.

```
budget = (прогноз_генерации_скорр + энергия_батареи) − ожидаемое_потребление
```

**Атрибуты:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `permissions` | `dict[str, bool]` | Словарь `{entity_id: True/False}` — разрешение для каждой управляемой нагрузки |
| `permissions_reasons` | `dict[str, str]` | Объяснение решения для каждой нагрузки |
| `forecast_remaining_kwh` | `float` | Скорректированный прогноз генерации (с учётом коэффициентов надёжности) |
| `forecast_raw_kwh` | `float` | Сырой прогноз генерации без коррекции |
| `forecast_correction_coefficient` | `float` | Итоговый смешанный коэффициент (blended) |
| `forecast_hist_coefficient` | `float` | Исторический коэффициент надёжности прогноза (факт/ожидание за N дней) |
| `forecast_today_coefficient` | `float` | Внутридневной динамический коэффициент (факт сегодня / ожидание к этому часу) |
| `battery_energy_kwh` | `float` | Текущая энергия батареи = SOC/100 × ёмкость |
| `expected_consumption_until_0800_kwh` | `float` | Ожидаемое потребление с текущего часа до 08:00 следующего дня (с учётом коэффициента присутствия) |
| `occupancy_coefficient` | `float` | Применённый коэффициент присутствия (`1.0` если никто не ушёл или нет данных) |
| `efficiency_coefficient` | `float` | КПД инвертора — отношение (Генерация − Потери) / Генерация за period. `1.0` = сенсор не настроен или недостаточно данных. Зажат в [0.70, 1.0] |
| `debug_actual_today` | `float` | Фактическая генерация сегодня (для отладки) |
| `debug_expected_today_total` | `float` | Максимальный прогноз за сегодня (`temp_max_forecast`) |
| `debug_expected_today_so_far` | `float` | Сколько из прогноза ожидалось к этому часу |
| `debug_fraction_so_far` | `float` | Доля исторического суточного профиля до текущего часа |

**Алгоритм расчёта бюджета** — см. [раздел ниже](#алгоритм-расчёта-бюджета).

**Алгоритм разрешений (permissions):**  
Нагрузки сортируются по приоритету (поле `priority` в `deduct_settings`). Бюджет расходуется последовательно:

1. Если активен режим экспортного пика (`is_export_peak`) → блокировать всё
2. Если нагрузка требует `only_solar_or_negative_price`, и сейчас нет солнца/нет нулевой цены → блокировать
3. `req_kwh = 0` (динамическая нагрузка без нормы):
   - Разрешить если `available_budget > 0` и мощность достаточна
4. `req_kwh > 0` (нагрузка с суточной нормой кВт·ч):
   - `needed = req_kwh − consumed_today`
   - Разрешить если `available_budget >= needed`, затем `available_budget -= needed`

### 5. Инвертор: Команда режима (Inverter Mode Command)

**Имя:** `Inverter Mode Command`

**Состояние:** Одно из следующих строковых значений:

| Значение | Описание |
|----------|----------|
| `sale_pv` | Продажа только от PV. Батарея не задействована |
| `sale_pv_bat` | Продажа от PV + батарея. Активна стратегия SELL |
| `sale_pv_no_bat` | Продажа PV без батареи при высокой цене продажи в дневное время |
| `buy` | Зарядка батареи от сети (активна стратегия BUY) |
| `stop_sale` | Запрет продажи (цена ниже порога `price_stop_sell`) |
| `bat_emergency` | Аварийный заряд: SOC ≤ `min_soc` |

**Логика выбора режима (приоритет сверху вниз):**

1. `bat_emergency` — если SOC ≤ min_soc
2. `stop_sale` — если текущая цена продажи < `price_stop_sell`
3. `buy` — если активна стратегия покупки (Market BUY Active)
4. `sale_pv_bat` — если активна стратегия продажи (Market SELL Active)
5. `sale_pv_no_bat` — если цена продажи ≥ `price_sell_only_pv` И есть реальный солнечный профицит И время < `sale_pv_no_bat_max_hour`
6. `sale_pv` — значение по умолчанию

**Атрибуты:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `mode_reason` | `str` | Объяснение выбранного режима |
| `is_preparing_for_peak` | `bool` | `True` если BMS-симуляция показывает нехватку времени для заряда до пика продажи |
| `next_peak_start_hour` | `str` | Время следующего ценового пика продажи (`"Сегодня 17:00"` / `"Завтра 08:00"` / `"Нет пика сегодня"`) |
| `bms_forecast` | `dict` | Детальный отчёт BMS-симуляции (см. ниже) |
| `charge_target_soc` | `float` | *Только в режиме `buy`* — целевой SOC для зарядки |
| `charge_reason` | `str` | *Только в режиме `buy`* — причина зарядки (`"price"` / `"survival"` / `"idle"`) |

**Структура `bms_forecast`:**

| Поле | Тип | Описание |
|------|-----|----------|
| `status` | `str` | Статус: `"Штатный заряд к пику"`, `"Внимание: Подготовка к Пику"`, `"Зарядка отложена (ждем дешевых часов)"`, `"Прогноз заряда до конца дня (пиков нет)"` |
| `success` | `bool` | `True` если батарея успеет зарядиться до пика |
| `target_soc` | `float` | Целевой SOC |
| `hours_available` | `int` | Сколько часов осталось до пика |
| `final_simulated_soc` | `float` | Финальный SOC по симуляции |
| `log` | `list[dict]` | Почасовой лог симуляции (час, профицит солнца, лимит BMS, реальный заряд, SOC) |

### 6. Прогноз разряда батареи (Battery Depletion Forecast)

**Имя:** `Battery Depletion Forecast`

**Состояние:** Строка с временем, когда батарея предположительно достигнет `min_soc`:
- `"Сегодня в 22:00"`
- `"Завтра в 04:00"`
- `"Послезавтра в 06:00"`
- `"> 48 часов"` — не разрядится в ближайшие 48 часов
- `"Нет батареи"` / `"Уже разряжена"`

**Алгоритм:**
1. Берётся текущий SOC батареи
2. Симулируется почасовое изменение SOC на 48 часов вперёд:
   - Потребление берётся из усреднённого профиля (с учётом дня недели)
   - Генерация корректируется прогнозом (`forecast_today`, `forecast_tomorrow`)
   - При зарядке применяется кривая CC/CV: `actual_charge = min(net_solar × eff_coeff, accepted_power)`
   - При разряде применяется учёт КПД: `soc_delta = (net_cons / eff_coeff) / capacity × 100`
3. Возвращается час, когда SOC впервые опускается ≤ `min_soc`

**Атрибуты:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `initial_soc` | `float` | Текущий SOC батареи (%) |
| `battery_capacity` | `float` | Ёмкость батареи (кВт·ч) |
| `min_soc_target` | `float` | Целевой минимум SOC |
| `hours_to_depletion` | `int` | Через сколько часов достигнет min_soc |
| `final_simulated_soc_48h` | `float` | SOC через 48 часов (если не разрядится раньше) |

### 7. Прогноз заряда к закату (Battery End of Day SOC)

**Имя:** `Прогноз заряда к закату`

**Единица:** %

**Состояние:** Предсказанный SOC батареи к моменту заката (последний час с генерацией > 0.05 кВт·ч).

**Алгоритм:**
1. Определяется час заката — последний час профиля генерации с > 0.05 кВт·ч
2. Симулируется SOC с текущего часа до заката:
   - Прогноз генерации масштабируется по `forecast_today_remaining`
   - Зарядка через CC/CV кривую: `actual_charge = min(net_solar × eff_coeff, accepted_power)`
   - Потребление из профиля (с учётом дня недели): `soc_delta = (net_cons / eff_coeff) / capacity × 100`
3. Возвращается финальный SOC в процентах

**Атрибуты:**

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `initial_soc` | `float` | Стартовый SOC (%) |
| `battery_capacity` | `float` | Ёмкость (кВт·ч) |
| `sunset_hour` | `str` | Расчётный час заката (`"17:00"`) |
| `expected_remaining_gen` | `float` | Ожидаемая оставшаяся генерация до заката (кВт·ч) |
| `hourly_simulation` | `dict[str, float]` | Почасовой SOC симуляции (`{"14:00": 72.3, "15:00": 84.1, ...}`) |
| `status` | `str` | `"Генерация завершена"` — если текущий час уже после заката |

## Алгоритм расчёта бюджета

**Функция:** `get_budget_and_permissions(days_for_profile, skip_strategy_check)`

### Шаг 1 — Прогноз генерации

```
forecast_raw = сумма значений forecast_today_remaining сенсоров

# Исторический коэффициент надёжности (за N последних дней)
hist_coeff = Σ(actual) / Σ(forecast)  [из forecast_history]
           → зажат в [0.2 ... 2.0]

# Внутридневной коэффициент
fraction_so_far = hist_gen_до_текущего_часа / hist_gen_суточная
actual_today_gen = Σ(generation today profile)
expected_so_far = temp_max_forecast × fraction_so_far

today_coeff = actual_today_gen / expected_so_far  [зажат в 0.2…2.0]

# Смешанный (blended) коэффициент
blended = today_coeff × fraction_so_far + hist_coeff × (1 − fraction_so_far)

forecast_adjusted = forecast_raw × blended
```

### Шаг 2 — Энергия батареи

```
batt_energy = battery_capacity × (soc / 100) × eff_coeff
```

Где `eff_coeff = get_efficiency_coefficient()` — коэффициент DC→AC потерь. Если не настроен — `1.0`.

### Шаг 3 — Ожидаемое потребление до 08:00

```
prof_today = get_average_profile("consumption_base", days, weekday|weekend)
prof_tom   = get_average_profile("consumption_base", days, weekday|weekend)

expected_consumption = Σ prof_today[h] для h ∈ [cur_hour .. 23]
                     + Σ prof_tom[h]   для h ∈ [0 .. 7]

# Корректировка на присутствие
expected_consumption × = occupancy_coefficient
```

### Шаг 4 — Итоговый бюджет

```
budget = (forecast_adjusted × eff_coeff) + batt_energy − expected_consumption
```

Где:
- `forecast_adjusted` — скорректированный прогноз генерации
- `eff_coeff` — дополнительное умножение на потери инвертора (note: `batt_energy` уже умножена на `eff_coeff` на шаге 2)

### Шаг 5 — Разрешения нагрузок

Нагрузки обрабатываются по возрастанию приоритета. `available_budget` уменьшается при каждом разрешении.

## Алгоритм рыночной стратегии

**Функция:** `get_market_strategy(mode: "buy"|"sell")`

Анализирует окно **48 часов** (сегодня + завтра).

### Режим BUY (покупка)

1. Ищутся часы с ценой ≤ `price_buy_limit` (учитывается `price_tolerance`)
2. При отрицательных ценах — немедленный "carte blanche", цель 100% SOC
3. Включается **Логика выживания** (Survival Bridge):
   - Симулируется SOC на 48 часов вперёд с учётом CC/CV и прогнозов генерации
   - Если SOC опустится ниже `min_soc` — добавляется дешевейший промежуточный час зарядки ("мост")
   - Итерация повторяется до стабильного результата
4. Вычисляется `target_soc` (умный AI или фиксированный)
5. Рассчитывается `charge_plan` — мощность по часам с учётом CC/CV и уже имеющегося SOC

### Режим SELL (продажа)

1. Ищутся часы с ценой ≥ `price_sell_limit`
2. При отрицательной цене прямо сейчас — продажа блокируется полностью
3. Если пики есть **и сегодня, и завтра** — проверяется возможность перезарядки между пиками:
   - Через дешёвую сеть (`price_buy_limit`)
   - Через солнечную генерацию (прогноз > 3 кВт·ч днём)
   - Через световой день (fallback)
   - Если перезарядка невозможна — выбирается пик с более высокой ценой
4. `target_soc` для продажи = `max(target_soc_sell, expected_night_consumption / capacity × 100)` — резерв на ночь

## Алгоритм прогноза батареи

**В сенсоре `Inverter Mode Command`**, функция `_calculate_mode()`:

Перед тем как выставить режим `sale_pv_bat`, система проверяет — успеет ли батарея зарядиться до целевого SOC к часу пика продажи:

1. Определяется `peak_start_hour` — ближайший час из плана продаж
2. Симулируется SOC от текущего момента до `peak_start_hour` с шагом 1 час:
   - В каждом часу: `net_gen = expected_gen − expected_cons` (с прогнозными коэффициентами)
   - Зарядка = `min(net_gen, max_power × CC/CV_ratio)`
   - SOC накапливается
3. **Статусы:**
   - `"Внимание: Подготовка к Пику"` (success=false) — не успевает заряд, `is_preparing_for_peak=True`, режим меняется на блокировку разряда
   - `"Зарядка отложена (ждем дешевых часов)"` — зарядки хватает, но есть запас времени, можно ждать
   - `"Штатный заряд к пику"` (success=true, is_preparing=True) — в критическом окне заряда, блокировать разряд
   - `"Прогноз заряда до конца дня (пиков нет)"` — активных пиков нет

## Алгоритм учёта присутствия

**Функции:** `get_current_occupancy()`, `get_occupancy_coefficient(hour)`

### Запись данных

Каждый час в момент сброса (`_async_reset_hour`):
```python
occ_count = get_current_occupancy()  # кол-во person.* == "home" или binary_sensor.* == "on"
data["consumption_total"][str(past_hour)].append({
    "v": kWh_value,
    "wd": weekday,
    "occ": occ_count   # -1 = не настроено, 0 = никого, N = N человек
})
```

Данные без `occ` (старые записи) — игнорируются при расчёте коэффициента (backward compatible).

### Расчёт коэффициента

```python
# По истории за custom_period дней:
for каждый час:
    for каждая запись с occ != None:
        if occ > 0:  home_total += v; home_count += 1
        else:        away_total += v; away_count += 1

avg_home = home_total / home_count
avg_away = away_total / away_count

if home_count < 5 or away_count < 3:
    return 1.0  # недостаточно данных

if current_occ == 0:
    return clamp(avg_away / avg_home, 0.1, 1.0)
else:
    return 1.0  # люди дома — корректировка не нужна
```

### Применение

В `get_budget_and_permissions()`:
```python
expected_consumption *= get_occupancy_coefficient()
```

Коэффициент масштабирует прогнозируемое потребление — при отсутствии жильцов бюджет автоматически растёт, что позволяет дополнительно разрешить управляемые нагрузки (стирку, нагрев бойлера и т.д.).

## Алгоритм расчёта КПД инвертора

**Функция:** `get_efficiency_coefficient()`

### Требования

- Настроен `inverter_losses_sensor` в config
- Накоплено ≥ 5 часов с `current_generation > 0.01` кВт·ч

### Алгоритм

```python
# За custom_period дней по каждому часу:
total_gen   = Сумма generation за период (> 0.01 кВт·ч любой час)
total_loss  = Сумма losses за те же часы

# Если меньше 5 часов с данными:
return 1.0

# Иначе:
eff = (total_gen - total_loss) / total_gen
return clamp(eff, 0.70, 1.0)
```

### Применение

| Место | Формула |
|------|--------|
| `get_budget_and_permissions()` — прогноз | `forecast_adjusted × eff_coeff` |
| `get_budget_and_permissions()` — батарея | `batt_energy = soc/100 × capacity × eff_coeff` |
| `BatteryDepletionTimeSensor` — разряд | `soc_delta = (net_cons / eff_coeff) / capacity × 100` |
| `BatteryDepletionTimeSensor` — заряд | `actual_charge = min(net_solar × eff_coeff, accepted_power)` |
| `BatteryEndOfDaySOCSensor` — разряд | Аналогично Depletion |
| `BatteryEndOfDaySOCSensor` — заряд | Аналогично Depletion |
